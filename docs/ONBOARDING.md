# New-account onboarding

New `users/{uid}` profiles created through email, Google or phone sign-in receive an explicit version-1 `onboarding` map. Profiles that already exist are never rewritten or opted into onboarding, even if incomplete. Existing imported profiles retain the legacy behavior. Completion is stored against the Firebase UID, not browser storage. Different unlinked authentication identities remain separate accounts.

The four steps collect full name and optional city; college/course/study stage/graduation year; skills, professional direction and career goals; then collaboration preferences and optional discovery consent. The same uppercase name normalizer is used for phone login, onboarding and profile edits. Google names are prefilled and must pass full-name validation before continuing. Other scripts/imports and legacy names are not bulk modified.

Each Continue transaction saves private core fields in `users/{uid}`, private preferences under `careerPreferences`, the next resumable step, and the limited matching name directory in `adminUsers/{uid}`. Existing identity, email, createdAt, résumé and application records are not replaced. Save and sign out permits a partial draft and resumes on the saved step at the next login. No navigation occurs if the write fails. Back preserves the local form draft until its next successful save.

Completion atomically saves profile values, a completed timestamp, private `discoveryPreferences/{uid}` details and optional `memberProfiles/{uid}` projection. Discovery defaults off each new onboarding visit. If explicitly selected, only name and skills become public to signed-in members; `shareDetails` remains false. Contact information, education, availability, goals and résumé are not placed in the public projection. Existing team discovery settings can be managed in Find a team. Completed onboarding cannot be reset or removed under the rules; ordinary profile editing remains available.

Verified administrators retain their existing admin route. A global route gate intercepts unfinished new student accounts, including public return destinations after sign-in. The onboarding page resumes incomplete profiles and redirects completed/legacy profiles to a safe internal destination. Session restoration and permission failures retain the existing recovery UI. Completion navigation waits for the profile observer to confirm persisted state. Direct protected access with a missing profile initializes it idempotently through the existing profile transaction.

Deploy `firestore:rules` before releasing Hosting. New client profile creation includes the onboarding field, so old deployed rules will reject it. The JSON schema and rules are backward compatible with profiles without this optional field. No backfill, new index, production seed or deletion is required. Rules tests cover uppercase completion, state immutability, owner-only preferences and atomic consented publication.
